## 1. 产品概述

### 1.1 项目背景

本项目为《杀戮尖塔2》（Slay the Spire 2）的网页版复刻，旨在通过开源方式还原二代核心单人体验。项目定位为个人学习项目，完成后将上传至 GitHub / Gitee 供社区交流。

### 1.2 产品定位

| 维度       | 说明                                     |
| ---------- | ---------------------------------------- |
| 产品类型   | 网页端 Roguelike 卡牌构筑游戏            |
| 目标用户   | 个人学习 + 开源社区                      |
| 技术栈     | Vue 3 + TypeScript（纯前端，无后端）     |
| 视觉风格   | 还原原作暗黑哥特画风                     |
| 数据持久化 | localStorage / IndexedDB（元进度系统）   |
| 部署方式   | 静态站点托管（GitHub Pages / Vercel 等） |

### 1.3 MVP 范围边界

**包含**：

- 先古遗物选择（开局 Neow 祝福）
- 地图探索（三幕结构，MVP 先实现第一幕·密林）
- 多场战斗（普通 / 精英 / Boss）
- 商店系统
- 篝火（休息 / 升级卡牌）
- 事件系统（MVP：任意阶段 4 个 + 密林幕 12 个 = 16 个事件）
- 遗物系统
- 战士角色（完整卡池）
- 元进度系统（跨局解锁、战绩记录）
- 单局存档（继续游戏）
- 调试系统（木桩测试场 + 卡牌/遗物控制台）

**不包含（后续迭代）**：

- 攀升难度（Ascension）
- 多人合作模式
- 其他4个角色
- 其余阶段事件（暗港 / 巢穴 / 荣耀幕，按幕扩充）
- 药水系统
- 剧情叙事 / 时间线碎片

## 2. 核心玩法循环

### 2.1 单局流程

```
[主菜单] → [先古遗物选择] → [地图界面] → [节点交互]
    ↑                                        ↓
    │                              ┌─────────┴──────────────┐
    │                              ↓                         ↓
    │                        [战斗界面]              [非战斗节点]
    │                              ↓                 (商店/篝火/事件/未知)
    │                              ↓                         ↓
    │                        [奖励页面] ←────────────────────┘
    │                         ↓前进（返回箭头可回战斗界面）
    │                     [返回地图 / 下一层]
    │                              ↓
    │                      [Boss战胜利?]
    │                       ↙          ↘
    │                  是                否
    │                   ↓                 ↓
    └────────── [通关结算]          [死亡结算]
                    ↓                   ↓
              [更新元进度] ←────────────┘
                    ↓
               [返回主菜单]
```

> 任意局内界面（战斗/地图/事件/奖励等）可按 Esc 进入**暂停菜单**：继续 / 重打 / 控制台 / 存档退出 / 放弃本局（见 §3.11）。
> 主菜单可进入**测试场 / 控制台 / 卡牌图鉴 / 战绩统计**（见 §3.10）。

### 2.2 核心循环要素

| 环节     | 玩家行为                    | 系统反馈                     |
| -------- | --------------------------- | ---------------------------- |
| 地图选择 | 点击可达节点                | 高亮路径、显示节点类型图标   |
| 战斗出牌 | 拖拽/点击卡牌 → 选择目标    | 播放攻击/防御动画、数值飘字  |
| 回合结束 | 点击"结束回合"按钮          | 弃牌动画、敌人行动、意图更新 |
| 战斗奖励 | 选择卡牌奖励 / 跳过         | 卡牌加入牌组、金币增加       |
| 商店交互 | 购买/移除卡牌、购买遗物     | 金币扣除、物品获得提示       |
| 篝火选择 | 休息(回血) / 升级(强化卡牌) | HP恢复动画 / 卡牌升级特效    |

## 3. 功能模块详细需求

### 3.1 先古遗物选择（Neow Blessing）

**功能概述**：每局开始时，玩家在密林幕**第1层「先古之民」节点**迎接涅奥 Neow，从 3 件候选遗物中选择 1 件作为本局起始遗物。

**触发条件**：新游戏开始（**自第 2 局起**；首局无此环节，第 1 层直接为普通节点）

**处理逻辑**：

1. 系统从涅奥遗物池（30 件）中随机抽取 3 件不重复的遗物
2. 展示每件遗物的名称、图标、效果描述
3. 玩家点击选择后，该遗物加入本局遗物列表并立即生效

### 3.2 地图系统

**功能概述**：生成并展示分层分支路径图，玩家沿路径选择节点推进游戏进程。整体采用**三幕（阶段）结构**，MVP 先完整实现**第一幕·密林（Overgrowth）**，其余幕后续迭代加入。

**地图总览（三幕结构）**：

| 幕       | 场景                                                | 层数                 | 状态                |
| -------- | --------------------------------------------------- | -------------------- | ------------------- |
| 第一阶段 | 密林（Overgrowth）**或** 暗港（Underdocks），二选一 | 17 层                | 🟢 MVP 实现（密林） |
| 第二阶段 | 巢穴（Hive）                                        | 16 层（第 18~33 层） | ⏳ 后续加入         |
| 第三阶段 | 荣耀（Glory）                                       | 15 层（第 34~48 层） | ⏳ 后续加入         |

> 完整地图数据见 `document/Overgrowth.md`（当前幕）及 `Underdocks.md` / `Hive.md` / `Glory.md`（后续幕）。

#### 3.2.1 密林幕地图结构参数（当前 MVP）

| 参数       | 值        | 说明                                  |
| ---------- | --------- | ------------------------------------- |
| 总层数     | 17        | 第 1~17 层                            |
| 分支路线数 | 2~5 条/层 | 每层生成 2~5 条平行路径，玩家择一前行 |
| Boss 层    | 第 17 层  | 3 个首领中三选一                      |
| 固定楼层   | 见下表    | 强制内容，不参与随机                  |

**固定楼层**：

| 楼层     | 固定内容                                                                   |
| -------- | -------------------------------------------------------------------------- |
| 第 1 层  | **先古之民**（自第 2 局游戏起，玩家在此迎接涅奥 Neow；首局从普通节点开始） |
| 第 2 层  | 必定为一场**普通怪物**战斗                                                 |
| 第 10 层 | 必定为**宝箱房**                                                           |
| 第 16 层 | 必定为**休息处**（篝火）                                                   |
| 第 17 层 | **Boss 战**                                                                |

**节点类型及概率**（非固定楼层）：

| 类型       | 图标 | 出现概率 | 约束                                       |
| ---------- | ---- | -------- | ------------------------------------------ |
| 普通战斗   | ⚔️   | 40%      | 前 3 场从弱怪池抽取，第 4 场起从强怪池抽取 |
| 精英战斗   | 💀   | 15%      | 精英池 3 个循环抽取（打完全部后重置）      |
| 未知（？） | ❓   | 20%      | 进入后内部再抽取内容（详见下方）           |
| 商店       | 🛒   | 10%      | —                                          |
| 篝火       | 🔥   | 15%      | 第 16 层固定 1 个                          |

> 注：宝箱**无概率**，仅第 10 层固定 1 个；概率合计 100%，实际生成受固定楼层与连通性约束调整。

**未知（？）房间内部内容概率**（wiki 数据）：

进入「未知（？）」房间后，内容从 5 种类型中抽取：

| 类型 | 基础概率 | 说明                                                     |
| ---- | -------- | -------------------------------------------------------- |
| 事件 | 85%      | 从当前幕事件池抽取（详见 §3.7）                          |
| 战斗 | 10%      | 从普通战斗池抽取                                         |
| 商店 | 3%       | 不会出现在上一层为商店、或可进入的下一层全部是商店的位置 |
| 宝箱 | 2%       | —                                                        |
| 精英 | 0%       | 常规为 0（特定效果「致命事件」下基础/叠加概率变为 10%）  |

**叠加概率机制**：除事件外，某类型未出现时，下次抽中概率增加其基础值；出现后重置为基础值。示例（正常游玩）：

- 第 1 个未知房：**事件 85% / 战斗 10% / 商店 3% / 宝箱 2%**
- 若第 1 个出事件，第 2 个：**事件 70% / 战斗 20% / 商店 6% / 宝箱 4%**
- 若第 2 个继续出事件，第 3 个：**事件 55% / 战斗 30% / 商店 9% / 宝箱 6%**

**新手保护**：总局数为 0 的新游戏，前 2 个未知房**固定为事件**，第 3 个固定为战斗。

> 注：持有「佛珠手链」遗物时未知房不会出现战斗；「黄金罗盘」使第 2 阶段未知房只出事件（后续遗物扩展）。

#### 3.2.3 密林幕怪物数据（数据源：`document/Overgrowth.md` §3）

> 行为模式即**意图循环**：敌人按固定序列循环预告并执行意图，满足条件（如 HP 阈值 / 被击晕）时切换阶段；HP 标注 `区间下限~区间上限` 表示基础难度下在该区间内随机。怪物立绘/头像图片路径规划见 §5.4。

**① 弱怪池（前 3 场普通战斗）**

**毛绒伏地虫**（`fuzzy_wurm_crawler`）｜HP 55~57｜普通｜初始能力：无

- 行为模式：酸液黏球起手 → 吸气 → 酸液黏球…（永久循环）
- 招式：酸液黏球＝造成 4 点伤害；吸入＝获得 7 点力量

**小啃兽**（`nibbit`）｜HP 42~46｜普通｜初始能力：无

- 行为模式：单只以顶撞起手；双只时前排以犹豫斩击、后排以哈气起手；循环 犹豫斩击→哈气→顶撞
- 招式：顶撞＝12 点伤害；犹豫斩击＝6 点伤害 + 获得 5 点格挡；哈气＝获得 2 点力量

**缩小甲虫**（`shrinker_beetle`）｜HP 38~40｜普通｜初始能力：无

- 专属机制：**缩小** — 玩家造成的攻击伤害减少 30%
- 行为模式：缩小（仅第 1 回合）→ 大啃 → 践踏 → 大啃 → 践踏…（永久交替）
- 招式：缩小＝给予玩家【缩小】；大啃＝7 点伤害；践踏＝13 点伤害

**树叶史莱姆（小）**（`leaf_slime_s`）｜HP 11~15｜普通｜初始能力：无

- 行为模式：第 1 回合冲撞/黏液等概率随机起手，之后永久交替循环
- 招式：冲撞＝3 点伤害；黏液＝向弃牌堆洗入 1 张【黏液】

**树叶史莱姆（中）**（`leaf_slime_m`）｜HP 32~35｜普通｜初始能力：无

- 行为模式：黏糊射击起手 → 团块射击 → 黏糊射击…（永久交替）
- 招式：黏糊射击＝向弃牌堆洗入 2 张【黏液】；团块射击＝8 点伤害

**树枝史莱姆（小）**（`twig_slime_s`）｜HP 7~11｜普通｜初始能力：无

- 行为模式：永远只重复同一招
- 招式：冲撞＝4 点伤害

**树枝史莱姆（中）**（`twig_slime_m`）｜HP 26~28｜普通｜初始能力：无

- 行为模式：黏糊射击必为第 1 回合行动，之后必接戳刺扑击；戳刺扑击不可连续使用超过 2 次

### 3.3 战斗系统

#### 3.3.1 战斗初始化

1. 根据节点类型加载对应敌人配置
2. 初始化玩家战斗状态：能量重置、Buff/Debuff清空、格挡归零
3. 洗牌：将牌组洗入抽牌堆
4. 触发 `ON_COMBAT_START` 遗物效果
5. 进入第一回合

#### 3.3.2 回合流程

**玩家回合开始**：

1. 触发所有 `ON_TURN_START` 遗物和效果
2. 能量重置为 `baseEnergy + 修正值`
3. 抽取卡牌（默认5张，受遗物/效果修正）
4. 更新敌人意图显示
5. 等待玩家操作

**玩家行动阶段**：

- **拖拽出牌**：拖出手牌时，卡牌在手牌区上方浮起（**不脱离手牌区**），拖至目标上方释放
- **目标选择**：需要选择目标的卡牌，拖拽时出现**箭头**指向怪物供选择；**仅 1 个怪物时自动直接使用**，不出现箭头
- 每张卡打出后立即结算效果链
- 可随时查看抽牌堆/弃牌堆剩余数量
- 能量不足时卡牌置灰不可用

**回合结束**：

1. 手牌全部移入弃牌堆
2. 触发所有 `ON_TURN_END` 效果
3. Buff/Debuff持续时间递减，归零时移除
4. 格挡清零（除非有保留效果）
5. 进入敌人回合

**敌人回合**：

1. 按敌方站位顺序依次行动
2. 每个敌人执行**当前意图**对应的动作（意图预告在玩家回合开始前更新）
3. 意图由**行为模式循环**决定：敌人按固定循环出招（如 墨迹→墨水长枪→肢解→准备→循环），部分敌人按 HP/条件切换阶段（如仪式兽被击晕后进入狂暴二阶段）
4. 结算完毕后检查胜负条件
5. 未结束则回到玩家回合开始

> 各敌人的行为模式（意图循环）与招式数值见 §3.2.3（密林幕完整数据，源自 `document/Overgrowth.md` §3），导入时映射为 `data/enemies.json` 的 `aiPattern` 字段。

#### 3.3.3 伤害计算

**攻击伤害**：

$$
\text{攻击伤害} = \left\lfloor (\text{基础值} + \text{力量}) \times \text{易伤修正} \times \text{虚弱修正} \times \text{其他倍率} \right\rfloor
$$

**格挡获得**：

$$
\text{格挡获得} = \text{基础值} + \text{敏捷}
$$

| 修正                 | 基础值                | 遗物强化后 |
| -------------------- | --------------------- | ---------- |
| 易伤（受到伤害增加） | ×1.5                  | 纸蛙 ×1.75 |
| 虚弱（造成伤害降低） | ×0.75                 | 纸鹤 ×0.6  |
| 力量                 | 每层使每段攻击伤害 +1 | —          |
| 敏捷                 | 每层使格挡 +1         | —          |

- 结算顺序：计算攻击伤害 → 扣除格挡 → 剩余伤害扣血 → 触发受伤相关效果
- 格挡独立扣除：$\text{扣血} = \max(0, \text{最终伤害} - \text{格挡})$

#### 3.3.4 胜负判定

- **胜利**：所有敌人HP ≤ 0 → 进入奖励结算
- **失败**：玩家HP ≤ 0 → 进入死亡结算

#### 3.3.7 奖励页面（Reward Page）

**功能概述**：战斗胜利后展示本场奖励的页面，支持返回战斗界面查看与前进至地图。

**布局**（居中方框内，从上到下）：

| 顺序 | 内容     | 说明                                                   |
| ---- | -------- | ------------------------------------------------------ |
| 1    | 金币     | 按战斗类型掉落（普通 15~~25 / 精英 30~~45 / Boss 100） |
| 2    | 药水     | **预留位置**（药水系统上线后启用，MVP 隐藏或显示占位） |
| 3    | 遗物     | 精英/Boss 战出现（普通战无此区块）                     |
| 4    | 卡牌奖励 | 3 选 1，按奖励质量分级（普通/罕见/稀有）               |

**导航**：

- 方框下方左右两侧各有**返回箭头按钮（←）**与**前进箭头按钮（→）**
- **返回箭头**：回到进入奖励页之前的页面——战斗结束后的奖励页点击返回 → 回到**战斗界面**（已结算状态，仅可查看战场）；返回后仍可通过前进箭头再次进入奖励页
- **前进箭头**：前往**地图界面**，继续爬塔
- 卡牌奖励无论是否选择均可前进（未选择默认跳过）

**边界条件**：

- 无对应奖励时不显示该区块（如普通战无遗物区块）
- 返回战斗界面仅查看，不可继续操作（防重复结算）

### 3.7 事件系统

**功能概述**：玩家进入地图上的「未知（？）」房间时触发随机剧情事件，阅读事件文本并从若干选项中选择，结算对应收益/代价。

**触发方式**：进入「未知（？）」节点 → 按内部概率判定内容（**事件 85% / 战斗 10% / 商店 3% / 宝箱 2%**，含叠加机制，见 §3.2）→ 若判定为事件，从当前幕事件池随机抽取 1 个 → 展示事件文本与选项

**事件池规则**：

- 事件池按阶段划分：**任意阶段事件**（任何阶段可出）+ **阶段事件**（仅对应幕出现）
- MVP 事件池 = 任意阶段 4 个 + 密林幕 12 个 = **16 个**（其中「药水的未来？」依赖药水系统暂剔除，实际生效 **15 个**）
- 完整事件数据（57 个，含选项效果与机制说明）见 `document/event.md`

**处理逻辑**：

1. 进入未知房间 → 从事件池随机抽取（按阶段过滤）
2. 展示事件文本（intro）与选项列表（致死选项标注危险提示）
3. 玩家选择选项 → 立即结算效果（生命/最大生命、金币、卡牌、遗物等）
4. 部分选项触发**事件专属战斗**（如「茂密的植被」→ 对战 4 只扭动虫）
5. 结算后返回地图

### 3.9 元进度系统

**功能概述**：跨局持久化数据，记录玩家成就和解锁进度。

**存储方案**：localStorage（主数据） + IndexedDB（战绩历史等大体积数据）

**数据结构**：

```typescript
interface MetaProgress {
  totalRuns: number
  wins: number
  bestFloor: number
  totalKills: number
  unlockedRelics: string[]
  unlockedCards: string[]
  characterStats: {
    warrior: {
      runs: number
      wins: number
      highestScore: number
    }
  }
  runHistory: RunRecord[]
  settings: GameSettings
}

interface RunRecord {
  id: string
  timestamp: number
  character: string
  floorReached: number
  result: 'WIN' | 'DEATH'
  score: number
  relicsCollected: string[]
  cardsCollected: number
}
```

**解锁规则（MVP）**：

| 解锁内容         | 条件                        |
| ---------------- | --------------------------- |
| 新遗物进入掉落池 | 首次通关 / 累计击杀特定敌人 |
| 新卡牌进入奖励池 | 使用特定卡牌组合通关        |
| 统计面板         | 完成首局                    |

**UI展示**：

- 主菜单显示总胜场、最高层数、最近战绩
- 收藏页面展示已解锁遗物/卡牌图鉴
- 每局结算页显示本局数据和历史对比

### 3.10 主菜单与调试系统

**功能概述**：主菜单为游戏入口界面，提供开始/继续/调试等入口。

**菜单项**：

| 菜单项   | 行为                                             |
| -------- | ------------------------------------------------ |
| 新游戏   | 开始新一局（若存在未完成存档，二次确认是否覆盖） |
| 继续游戏 | 读取单局存档继续（无存档时置灰禁用）             |
| 设置     | 基础设置：音乐/音效音量、动画开关、重置存档      |
| 测试     | 进入**测试场**（无限血木桩，见下）               |
| 控制台   | 展示全部卡牌与遗物数据（只读浏览）               |
| 卡牌图鉴 | 浏览全部/已解锁卡牌（含升级效果）                |
| 战绩统计 | 元进度战绩（胜场/最高层数/最近战绩）             |
| 退出     | 返回浏览器                                       |

**测试场（木桩测试）**：

- 进入一场特殊测试战斗：敌方为 **1 个木桩**（**无限 HP、不攻击**、无行为模式）

- 测试场可打开控制台自由增删卡牌/遗物
- 测试场**不产出奖励、不结算战绩、不影响元进度与存档**

**控制台（调试）**：

- **主菜单控制台**：只读展示全部卡牌与遗物（名称/费用/类型/效果/稀有度/升级效果）
- **游戏内控制台**（战斗/地图中）：展示全部卡牌与遗物，并支持：
  - **添加/删除牌组中的卡牌**（含升级版本）
  - **添加/删除身上的遗物**
  - 改动即时生效，用于调试卡组与遗物搭配
- 游戏内控制台入口：暂停菜单「控制台」

### 3.11 暂停与重打

**触发**：战斗与地图界面均可按 **Esc** 或点击暂停按钮

**暂停菜单**：

| 菜单项   | 行为                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 继续     | 关闭暂停，返回当前界面                                                                                                         |
| 重打     | **重新开始当前节点**：回到进入当前节点前的状态（战斗→重开本场战斗，敌人重置为初始，玩家 HP/牌组恢复进入前；事件/未知节点同理） |
| 控制台   | 打开游戏内控制台（增删卡牌/遗物）                                                                                              |
| 存档退出 | 保存当前局状态并返回主菜单                                                                                                     |
| 放弃本局 | 放弃当前局（清除存档）并返回主菜单（需二次确认）                                                                               |

**边界条件**：

- 重打恢复到"进入当前节点前"的完整快照（HP/金币/牌组/遗物/地图状态）
- Boss 战可重打（回到 Boss 战开始）
- 重打不结算战绩、不影响元进度

### 3.12 单局存档

**功能概述**：Web 环境下关闭标签页后仍可继续游戏，每局状态实时持久化。

**存储方案**：localStorage（单键 JSON：`sts2_run_v1`）

**存档数据结构**：

```typescript
interface RunSave {
  version: number // 存档格式版本号（不兼容时提示并清除）
  savedAt: number // 保存时间戳
  stage: 1 | 2 | 3 // 当前阶段
  floor: number // 当前楼层
  nodeId: string // 当前节点
  mapState: MapState // 地图生成状态（节点布局/访问标记/分支）
  player: {
    hp: number
    maxHp: number
    gold: number
    energy: number
    deck: string[] // 牌组（卡牌ID数组，升级用 id+ 标记）
    relics: string[] // 遗物ID数组
    potions: string[] // 药水（预留，MVP 为空）
  }
  battleState?: BattleState // 战斗进行中的快照（回合/意图/敌人状态/玩家状态）
  eventState?: any // 事件进行中状态
  counters: Record<string, number> // 跨战斗计数器（如开心小花回合、双截棍连击数）
}
```

**保存时机**：每次关键状态变更后——战斗结束、节点结算、购买、遗物拾取、进入新节点、暂停存档退出

**规则**：

- 战斗进行中暂停退出 → 保存战斗快照，继续游戏时**恢复战斗**
- 存档损坏 / 版本不兼容 → 提示并回退（清除存档）
- 新游戏覆盖存档前二次确认

**边界条件**：

- 放弃本局 → 清除存档
- 通关 → 清除存档（战绩并入元进度）

```

 │                   └─胜利/死亡─▶ SETTLEMENT ──▶ MENU
 │
```

- **UNKNOWN**：未知房间，先按内部概率判定内容（事件 85% / 战斗 10% / 商店 3% / 宝箱 2%，含叠加机制），再转入对应界面
- **REWARD**：可返回 BATTLE（已结算态仅查看），前进至 RUN
- **TEST / CODEX / STATS**：由主菜单进入，独立于局内状态机（不改变局内状态）

### 4.3 数据驱动设计

所有游戏内容通过JSON配置定义，运行时动态加载：

### 5.3 动画需求清单

| 动画            | 触发时机 | 时长  | 优先级 | 说明                                     |
| --------------- | -------- | ----- | ------ | ---------------------------------------- |
| 卡牌抽取        | 回合开始 | 300ms | 高     | **逐张出现并呈扇形分布**（详见下）       |
| 卡牌打出        | 确认出牌 | 200ms | 高     | —                                        |
| 卡牌悬停        | 鼠标悬停 | 150ms | 高     | **卡牌突出放大并展示完整内容**（详见下） |
| 伤害飘字        | 伤害结算 | 800ms | 高     | —                                        |
| 敌人攻击        | 敌人回合 | 400ms | 高     | —                                        |
| 格挡获得        | 防御结算 | 200ms | 中     | —                                        |
| Buff/Debuff施加 | 状态变更 | 300ms | 中     | —                                        |
| 敌人死亡        | HP归零   | 600ms | 中     | —                                        |
| 洗牌回抽        | 洗牌触发 | 500ms | 中     | **弃牌堆卡牌带流光回到抽牌堆**（详见下） |
| 地图移动        | 选择节点 | 500ms | 低     | —                                        |
| 遗物触发        | 钩子激活 | 400ms | 低     | —                                        |

**抽牌动画**：回合开始时，卡牌**逐张**从抽牌堆飞出（每张间隔约 60ms），并**呈扇形分布**落到手牌区；同回合内手牌重叠排列，扇形角度随手牌数量自适应。

**卡牌悬停**：鼠标移上卡牌时，卡牌**上移放大并高亮**，完整展示卡面内容（费用/类型/效果/升级标记）；相邻卡牌向两侧让位，避免遮挡。

**洗牌动画**：弃牌堆触发洗牌时，卡牌以**流光**（光带/粒子）效果逐张从弃牌堆飞回抽牌堆，随后抽牌堆计数更新。

#### 5.4.6 卡牌背景与边框（Card Background & Frame）

> **设计决策**：卡牌**不做单卡插画**；统一使用**灰色中性背景**（一张共享图或 CSS 纯色），通过**边框颜色**区分卡牌类别。边框颜色为 CSS `border-color`，无需单独图片资源。本方案取代原"按稀有度三套背景（灰/蓝/金）"的设计。

**背景与边框配色表（按卡牌类别）**：

| 卡牌类别                    | 背景 | 边框颜色 | 说明                       |
| --------------------------- | ---- | -------- | -------------------------- |
| 战士·普通（Warrior common） | 灰   | **红**   | 战士普通卡牌边框为红色     |
| 无色（Colorless）           | 灰   | 灰       | —                          |
| 衍生（Derived）             | 灰   | 灰       | —                          |
| 状态（Status）              | 灰   | 灰       | 普通状态牌；例外见「感染」 |
| 诅咒（Curse）               | 灰   | 紫       | —                          |
| 事件（Event）               | 灰   | 绿       | —                          |

> **配色说明**：上表"颜色"均指**边框颜色**，背景本身统一为灰色。稀有度如需额外体现，可通过角标宝石 / 边框粗细等方式叠加（可选，不强制）。

**特殊卡牌——感染（Infection）**：

- 为满足特殊美术需求，**状态牌中的「感染」牌不使用灰色背景**，而是以**蠕动的蛆**作为卡面背景，且为**动画背景**。
- 实现方式：**精灵图（Sprite Sheet）**，横向帧条 PNG，按 §5.4.8 的帧元数据（`frameCount`/`frameWidth`/`frameHeight`/`fps`）驱动，但**循环播放**（ambient loop，区别于动作动画播一次回 idle）。
- 占位：`assets/cards/infection_sheet.png`（单帧同卡牌尺寸，N 帧宽 = 单帧宽 × N）。

> 该精灵图仅用于「感染」这一种状态牌，其余状态牌仍用灰色背景 + 灰边框。

**占位资源**：

| 占位路径                           | 用途                                                      | 建议规格                         |
| ---------------------------------- | --------------------------------------------------------- | -------------------------------- |
| `assets/cards/bg_card.png`         | 共享灰色卡面背景（战士普通/无色/衍生/状态/诅咒/事件通用） | 卡牌尺寸（约 250×350），透明 PNG |
| `assets/cards/infection_sheet.png` | 「感染」状态牌的蛆动画背景（精灵图，循环播放）            | 单帧 250×350，横向帧条           |

**数据字段**：组件按卡牌 `type`/`category` 与 `rarity` 选取边框色与背景；`感染` 牌由 `id === "infection"`（或专门标记位）触发精灵图背景，无需在 `cards.json` 逐卡配置美术路径（背景/边框由类型推导，仅 `infection` 需指向 `infection_sheet.png`）。

> **文字遮罩约定**：卡牌费用/名称/效果文字绘制于背景图**上层**，背景图在文字区域做**暗化/半透明蒙版**处理（在 CSS 或图片本身预留安全区），确保文字清晰可读（详见 Q&A 第 2 问结论）。

#### 5.4.7 资源接入约定

- 图片引用统一走 `data/*.json` 的 `art` / `icon` 字段（已在 §4.4 各数据格式中预留），组件读取字段后 `new Image()` 或 `<img :src>` 加载。
- 缺失资源时组件渲染降级占位（颜色块 + 文字/首字），保证无图也能跑通。
- 所有美术资源最终归入 §4.1 的 `src/assets/` 对应子目录。

#### 5.4.8 精灵图（Sprite Sheet）播放约定

**布局**：每个动画动作打包为 **1 张横向帧条 PNG**，帧从左到右排列（首帧在最左）。单帧宽高固定，整图宽 = 单帧宽 × 帧数。

**帧元数据**（数据驱动，存于对应 `data/*.json` 的 `art.animations`，无需硬编码在组件里）：

```json
// 以 enemies.json 为例（角色同理，存于 characters.json）
"art": {
  "portrait": "assets/enemies/vantom/portrait.png",
  "sprite": "assets/enemies/vantom/idle.png",
  "animations": {
    "attack": {
      "sheet": "assets/enemies/vantom/atk_sheet.png",
      "frameCount": 4,
      "frameWidth": 300,
      "frameHeight": 500,
      "fps": 12
    }
  }
}
```

**播放方式（二选一，组件按元数据驱动）**：

- **CSS 方案**（DOM/异步组件）：用 `background-image` + `animation` 的 `steps(frameCount)` 在 `frameWidth × frameCount` 宽度内平移 `background-position`，时长 = `frameCount / fps`。
- **Canvas 方案**（粒子/高性能场景）：`ctx.drawImage(sheet, i*frameWidth, 0, frameWidth, frameHeight, x, y, w, h)` 按 `requestAnimationFrame` 逐帧裁剪绘制。

**约定**：

- 攻击动画**播放一次**后回到 `idle` 静态帧（非循环）。
- 帧数/帧率以数据为准，美术替换图片时只需保证单帧尺寸一致、更新 `frameCount`，逻辑无需改动。
- 无对应精灵图时，组件降级为静态 `idle.png` 或纯色块占位。
- 所有美术资源最终归入 §4.1 的 `src/assets/` 对应子目录。
