## 2. 各主题关键实现

### 2.1 遗物系统
- 通过 `registerRelic` 按钩子注册（ON_COMBAT_START / ON_TURN_START / ON_PICKUP / ON_DAMAGE_TAKEN / ON_ENEMY_DEATH / ON_STRENGTH_GAIN…），必须经引擎方法（startPlayerTurn/playCard/endOfTurn）调用，不能手动回合循环
- 复杂机制：纸蛙(×1.75)、纸鹤(×0.6)、钢笔尖(第10张攻击×2)、冰淇淋(能量结转)、奥利哈钢(格挡延续 orichalcum_carry)、石炉加湿器(休息+5血)、皇家枕头(休息+15血)
- 需要选牌界面的 ON_PICKUP 遗物：通过 `offerPick(PendingPick)` + `resolvePick` 落地（沉重石板、精准剪刀、橙型香盒、新叶、卷轴箱等）
- **暂缓/排除**：依赖剧情/地图导航 UI 的（winged_boots 羽翼之靴、lava_rock 熔岩石）；依赖未实现子系统的（giant_scroll、lost_and_found_box、potion_pouch、kaleidoscope 万花筒等）仍 excluded
- 配置规则（回血/最大生命）放 `gameConfig.ts` 的 RELIC，不硬编码

### 2.2 事件系统（全量 57 个）
- 事件数据全量抽取（`parse-events.mjs`，stage 含 any/overgrowth/harbor/nest/glory/phase1~3）；运行时密林地图仅触发 any+overgrowth，其余数据完备但当前不可达
- **按事件 ID 精确分发**（`applyEventEffect(eventId, option)`），取代文本正则匹配
- 事件专属卡（多尼斯异鸟蛋/天选芝士/历史课）与专属遗物（石之剑/藏宝图/菲涅耳透镜/大蘑菇）数据缺失时 `addCard`/`grantRelic` 自动降级随机并提示
- 通用操作抽为 store 辅助：`addRandomFromPool` / `upgradeRandomN` / `downgradeRandomN` / `copyDeck` / `swapRandomRelic` / `transformBasicTo` / `removeFromDeckById`；随机源统一 `rand: () => number`
- `enterEvent` 限定 `stage === 'any' || 'overgrowth'`，与密林地图对齐
- 事件完成必须调 `advanceAfterReward()` 解锁下一层，否则事件后卡死

### 2.4 其他卡/无色卡 + 关键词机制
- `parse-utils.mjs` 修复伤害判定 bug、新增"触发效果"与"永恒"关键词识别
- 复杂无色卡依赖选牌 UI 或条件引擎 → 效果降级为空链但 UI 保留原文，符合"未实现子系统仅中文提示"惯例
- 关键关键词机制均已接入引擎：
  - **固有**：开局入手牌（combatEngine.startOfCombat）
  - **保留(本回合)**：独立 `retainHandThisTurn` 标志，仅当回合生效、回合开始清零（区别于 card 关键词 retain）
  - **状态/诅咒回合末在手牌触发** 与 **抽到触发(虚空)**：独立 intrinsic 机制，与打出效果分离

## 7. 关键经验教训（本会话沉淀）

- **遗物钩子必须经引擎方法调用**：手动回合循环会绕过 startPlayerTurn 导致被动 hook 不触发（早期 bug）
- **歧义词先确认**："收缩/贴太近"可能指间距/尺寸/位置，不确定应追问或做可逆小改动；动画与布局分开验收
- **地图可进入性由"当前节点连线指向的下一层"决定**，非解锁整层后任意点击；enterNode 也需同样的可达性守卫
- **事件完成路径必须调 `advanceAfterReward()`**，否则未知节点→事件后卡死（此前只在战斗/商店/篝火/宝箱推进）
- **事件金币+生命组合**：旧逻辑会误把金币当生命扣，需区分参数类型
- **奥利哈钢格挡**：回合结束 blockExpires 清零，需 orichalcum_carry 延续到对手回合
- **卡牌"永恒"**：只解析关键词不够，行为(不可移除/变化)需在移除/变化辅助与候选 mutableDeckOptions 中分别拦截
- **附魔挂载在 Card 对象**（`card.enchantments`），与 upgrade 一样跨用例共享缓存 → 测试间需清理 `getCard(c)!.enchantments = undefined`
- **`addDeckCard` 是内部函数不对外暴露**；测试附魔加入牌组逻辑应走公开的 `claimCardReward`
- **数据生成脚本在 `src/scripts/`**（非 `scripts/`），入口 `generate.mjs`；`data/*.json` 由 md + 脚本生成，禁止手改
- **rand/gen 以楼层加盐实现确定性随机**，保证可复现（mulberry32）
- **精确间距需核算容器自身 padding**（BattleView 的 .battle padding: 10px 20px + .field padding 叠加 = 40px）
